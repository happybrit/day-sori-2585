# ذخیرهٔ پاسخ‌های سوری در دیتابیس

این مخزن روی GitHub Pages به شکل HTML ایستا اجرا می‌شود. مرورگر نمی‌تواند بدون افشای رمزهای مدیریتی به یک فایل خصوصی در گیت‌هاب اطلاعات اضافه کند. برای همین از **Supabase (PostgreSQL)** و دسترسی عمومیِ فقط ثبت (insert-only) استفاده شده است.

## مراحل فعال‌سازی

1. در https://supabase.com/dashboard یک پروژهٔ Supabase ایجاد کنید.
2. در بخش SQL Editor محتوای `sql/birthday-entries.sql` را اجرا کنید.
3. از تنظیمات پروژه، **Project URL** و **Publishable key** (معمولاً با `sb_publishable_` شروع می‌شود) را بردارید.
4. در فایل `birthday-db-config.js` مقدار `url` و `publishableKey` را قرار دهید. این دو مقدار برای مرورگر عمومی طراحی شده‌اند، ولی **secret key / service_role / رمز دیتابیس** را هرگز در گیت‌هاب یا کد HTML نگذارید.
5. مطمئن شوید **Data API** پروژه روشن و جدول `public.birthday_entries` در آن قابل دسترس باشد؛ در صورت غیرفعال‌بودن «Automatically expose new tables»، جدول را از بخش **Integrations → Data API** منتشر کنید.
6. سایت را از GitHub Pages باز کنید، یک آرزوی آزمایشی ثبت کنید، سپس در Supabase → Table Editor → `birthday_entries` بررسی کنید که رکورد آمده است. یک پاسخ کوییز هم آزمایش کنید.

## چه چیزهایی ثبت می‌شوند؟

- متن آرزو در **شیشهٔ آرزوها**
- جواب‌های انتخابی **کوییز شخصی**، **حدس ایموجی**، **محاسبهٔ سریع** و **تطبیق رنگ**
- امتیاز نهایی هر نوبت بازی هنگام بستن پنجرهٔ بازی (برای امتیاز مثبت)
- نتیجهٔ موفق **سودوکو** هنگام تأیید

هر رکورد دارای یک شناسهٔ تصادفی برای جلوگیری از ذخیرهٔ چندباره در زمان ارسال مجدد است. اگر اینترنت قطع شود، رکورد در صف محلی مرورگر می‌ماند و در بازدید بعدی/وصل‌شدن اینترنت مجدداً ارسال می‌شود. وقتی دیتابیس هنوز تنظیم نشده، آرزوها فقط روی دستگاه نمایش داده می‌شوند و صف هم برای فعال‌شدن بعدی نگهداری می‌شود. پاسخ‌های قبل از نصب این نسخه به‌صورت خودکار از حافظهٔ محلی مهاجرت نمی‌کنند.

## حریم خصوصی و محدودیت‌ها

**هیچ‌کس از طریق کلید عمومی اجازهٔ خواندن، ویرایش یا حذف داده‌ها را ندارد**؛ RLS و مجوزهای SQL جلوی آن را می‌گیرند. بااین‌حال، چون سایت عمومی است، *هر بازدیدکننده* می‌تواند دادهٔ جدید ارسال کند؛ ثبت‌ها از نظر هویت به‌صورت قطعی به سوری منتسب نیستند. برای محدودکردن نوشتن فقط به حساب تلگرام سوری یا جلوگیری از اسپم، باید اعتبارسنجی Telegram Mini App `initData` روی **سرور/Edge Function** و ترجیحاً rate limiting پیاده‌سازی شود. ادعای هویت فقط بر اساس `initDataUnsafe` یا فیلدهای قابل‌تغییر مرورگر ناامن است.

داده‌ها داخل Supabase نگهداری می‌شوند، نه GitHub. **مخزن عمومی را محل ذخیرهٔ متن آرزوهای شخصی نکنید.** اگر اصرار به ذخیره‌سازی در خود گیت‌هاب باشد، به یک واسط امن سروری و مخزن **خصوصی** (مثلاً GitHub Issues/API) نیاز است؛ GitHub دیتابیس تراکنشی واقعی نیست.

برای بررسی رکوردها از SQL Editor:
```sql
select created_at, event_type, content, details
from public.birthday_entries
order by created_at desc;
```
